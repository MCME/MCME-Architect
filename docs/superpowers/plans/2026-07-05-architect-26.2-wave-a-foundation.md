# MCME-Architect 26.2 — Wave A: Foundation & Verification Spikes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repoint the build to Paper 26.2, add the MockBukkit test dependencies, and resolve every verify-early gate so the compile-migration plan (Plan 2) can be written with no unknowns.

**Architecture:** This plan is deliberately investigation-and-config only — no source migration yet. Foundation tasks change `pom.xml`; spike tasks are bounded investigations, each ending by recording a decision in a findings doc that Plan 2 consumes. TDD begins in Plan 2 (vendored utils) and Wave C (behaviour fixes); foundation/spike tasks use a "do → verify exit criterion" structure instead of failing-test-first.

**Tech Stack:** Java 21+ (JDK 25 installed at `C:\Program Files\Microsoft\jdk-25.0.2.10-hotspot`), Maven, `paper-api` (target `26.1.2-stable`), MockBukkit, JUnit 5. Branch: `architect-rework-2026`.

## Task 2: Repoint `pom.xml` to Paper 26.2

**Files:**
- Modify: `pom.xml` (dependencies + compiler config)

- [ ] **Step 1: Update paper-api and the compiler release**

In `pom.xml`, change the paper-api version and confirm the JDK target. Replace:
```xml
        <maven.compiler.source>21</maven.compiler.source>
        <maven.compiler.target>21</maven.compiler.target>
```
with (bump to 21+ per what 26.x requires — verify in Step 2):
```xml
        <maven.compiler.source>21</maven.compiler.source>
        <maven.compiler.target>21</maven.compiler.target>
```
and change the paper-api dependency:
```xml
        <dependency>
            <groupId>io.papermc.paper</groupId>
            <artifactId>paper-api</artifactId>
            <version>26.1.2.build.72-stable</version>
            <scope>provided</scope>
        </dependency>
```
(Use the exact `26.1.2.build.72-stable` coordinate present in `.m2`; the `<release>21</release>` in the compiler plugin config must match the JDK target.)

- [ ] **Step 2: Verify the JDK requirement for paper-api 26.1.2**

Run:
```bash
unzip -p "$HOME/.m2/repository/io/papermc/paper/paper-api/26.1.2.build.72-stable/paper-api-26.1.2.build.72-stable.jar" META-INF/MANIFEST.MF | grep -i "Build-Jdk\|Java-Version" || true
javap -verbose -cp "$HOME/.m2/repository/io/papermc/paper/paper-api/26.1.2.build.72-stable/paper-api-26.1.2.build.72-stable.jar" org.bukkit.Bukkit 2>/dev/null | grep "major version" | head -1
```

`major version: 65` = Java 21, `69` = Java 25. If it requires >21, bump `maven.compiler.source/target/release` accordingly (JDK 25 is available). Record the confirmed JDK target in the findings doc.

Delete this block from `pom.xml` (the two uses migrate to Paper-native in Plan 2):
```xml

            <version>4.8.0</version>

```

## Task 5: Spike — view-distance native equivalent

ProtocolLib is being dropped. `SpecialBlockSign` → `Player#openSign` is a clean, known swap. `ViewDistanceListener` manipulates LOGIN / UNLOAD_CHUNK / VIEW_DISTANCE packets and cancels chunk-unloads — that may lack a 1:1 native API.

**Files:** none (investigation)

- [ ] **Step 1: Re-read the current ProtocolLib usage**

Read `src/main/java/com/mcmiddleearth/architect/viewDistance/ViewDistanceListener.java` and `ViewDistanceManager.java`. List each packet manipulation and what player-visible effect it produces (per-player client view distance; suppressing chunk unloads).

- [ ] **Step 2: Check the Paper Player API for equivalents**

Run:
```bash
JAR="$HOME/.m2/repository/io/papermc/paper/paper-api/26.1.2.build.72-stable/paper-api-26.1.2.build.72-stable.jar"
javap -cp "$JAR" org.bukkit.entity.Player | grep -iE "viewdistance|sendviewdistance|openSign" 
```
Expected: `setViewDistance`/`setSendViewDistance`/`setNoTickViewDistance` and `openSign`. Note which exist.

- [ ] **Step 3: Record the mapping and any gap**

In the findings doc: map each current ProtocolLib effect to a native call, or mark it as a behaviour change / documented stopgap (e.g. if there is no native equivalent for suppressing chunk-unloads, note that the "keep chunks loaded" behaviour is dropped). This becomes the concrete Plan 2 spec for the ProtocolLib removal task.

## Task 6: Spike — PluginUtils removal feasibility (`/checknbt` + plotStoring)

Removal is approved but gated on two unknowns.

**Files:** none (investigation)

- [ ] **Step 1: Inspect the one live NMS use**

Read `src/main/java/com/mcmiddleearth/architect/additionalCommands/ArchitectCommand.java` around the `checknbt` subcommand and its `AccessInventory.getItemNBT(item)` call. Note exactly what output it produces (a serialized NBT/data-component string for op display).

- [ ] **Step 2: Confirm a native 26.x equivalent exists**

Run:
```bash
JAR="$HOME/.m2/repository/io/papermc/paper/paper-api/26.1.2.build.72-stable/paper-api-26.1.2.build.72-stable.jar"
javap -cp "$JAR" org.bukkit.inventory.ItemStack | grep -iE "getPersistentDataContainer|serializeAsBytes|getData|toString"
javap -cp "$JAR" "io.papermc.paper.datacomponent.DataComponentType" 2>/dev/null | head -1 || echo "check paper datacomponent package"
```
Decision rule: if a native call can produce an equivalent op-readable dump (data-component API, `serializeAsBytes`, or PDC), removal is GO. If not, the op debug command can be dropped instead (still GO). Only a hard need for NMS with no native/drop option is NO-GO.

- [ ] **Step 3: Confirm `plotStoring.IStoragePlot` vendors cleanly**

Read `Clipboard.java`, `CopyPasteManager.java`, `UndoData.java`. Confirm `IStoragePlot` is an interface Architect implements/consumes with no transitive PluginUtils-internal coupling beyond what can be copied into `architect.util`.

- [ ] **Step 4: Record GO/NO-GO**

In the findings doc: record GO (with the chosen `/checknbt` approach: native call or drop) or NO-GO (fall back to "defer PluginUtils removal; keep consuming its 26.2 build"). Also record the confirmed list of PluginUtils components to vendor (from spec §6).

# MCME-Architect 26.2 — Wave A: Compile Migration — Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get MCME-Architect compiling on Paper `26.1.2-stable` — migrate the ProtocolLib uses to Paper-native, runtime-guard WorldEdit, make `/checknbt` native, refresh the protocol map, fix the Material/deprecated-API breakage, and land a first MockBukkit smoke test.

**Architecture:** This is a mechanical version migration, not feature work. TDD-first does **not** fit most of it — you cannot run a test until the code compiles, and the whole point is to reach a compiling state. So the compile tasks use a "change → `mvn compile` → fix" loop; the single MockBukkit smoke test (Task 8) lands last, once compilation is green, and the behaviour tests for these migrations belong to the later Wave C stabilize plan. All API mappings below are the concrete outputs of the Wave A spikes — see [findings doc](../specs/2026-07-05-architect-26.2-wave-a-findings.md).

**Tech Stack:** Java 25, Maven, paper-api `26.1.2.build.72-stable` (provided), MockBukkit `mockbukkit-v26.1.2:4.114.0`, JUnit 5. Branch `architect-rework-2026`. All Maven commands: prefix `JAVA_HOME="/c/Program Files/Microsoft/jdk-25.0.2.10-hotspot"`.

## Task 4: Runtime-guard the WorldEdit-selection features

**Files:**
- Modify (add a presence check before each WE-selection use): `copyPaste/CopyCommand.java`, `copyPaste/CutCommand.java`, `serverResoucePack/RpCommand.java`, `noPhysicsEditor/NoPhysicsCommand.java`, `specialBlockHandling/itemBlock/ItemBlockCommand.java`, `serverResoucePack/RegionEditConversation/RegionEditPrompt.java`
- Create: `src/main/java/com/mcmiddleearth/architect/util/WorldEditGuard.java`

**Why (findings §Task 7):** no 26.x WorldEdit build exists upstream; on a 26.2 server WorldEdit may be absent, so `WEUtil` (which reads the player's WE selection) would fail. Guard so these features degrade gracefully.

- [ ] **Step 1: Create the guard helper**

```java
package com.mcmiddleearth.architect.util;

import org.bukkit.Bukkit;
import org.bukkit.command.CommandSender;
import com.mcmiddleearth.architect.PluginData;

public final class WorldEditGuard {
    private WorldEditGuard() {}

    public static boolean isAvailable() {
        return Bukkit.getPluginManager().getPlugin("WorldEdit") != null;
    }

    /** Returns true if WE is available; otherwise messages the sender and returns false. */
    public static boolean require(CommandSender cs) {
        if (isAvailable()) return true;
        PluginData.getMessageUtil().sendErrorMessage(cs,
            "This feature needs WorldEdit, which isn't available on this server version yet.");
        return false;
    }
}
```

- [ ] **Step 2: Guard each WE-selection call site**

In each listed file, immediately before the first `WEUtil.*` selection call in the relevant command path, add:
```java
        if (!WorldEditGuard.require(sender)) return true; // (use the local CommandSender/Player var name)
```
Read each file first to place the guard at the correct point and use the correct sender variable. Add `import com.mcmiddleearth.architect.util.WorldEditGuard;`.

- [ ] **Step 3: Verify + commit**

```bash
JAVA_HOME="/c/Program Files/Microsoft/jdk-25.0.2.10-hotspot" mvn -o compile 2>&1 | grep -iE "WorldEditGuard|CopyCommand|CutCommand" || echo "no errors in guarded files"

**Files:** whatever `mvn compile` reports — expected clusters in `specialBlockHandling/specialBlocks/*`, `blockData/*`, `signEditor/*`, `bannerEditor/*`.

This is the one task whose exact edits only the compiler can enumerate (which is why it needs Task 0's MCME-Connect gate first). Apply the known transformations; for anything else the compiler surfaces, apply the equivalent modern API.

```

- [ ] **Step 2: Fix the known categories**

- **Material renames:** `Material.GRASS` → `Material.SHORT_GRASS`; and any other `cannot find symbol ... Material.<X>` — look up the 26.x replacement constant (e.g. via `javap -cp <paper-api jar> org.bukkit.Material | grep -i <stem>`). Do not delete a block type; map it.
- **ItemStack durability:** `new ItemStack(mat, amount, (short) dmg)` and `item.setDurability(short)`/`getDurability()` → use `ItemMeta`/`Damageable`: `Damageable meta = (Damageable) item.getItemMeta(); meta.setDamage(dmg); item.setItemMeta(meta);` (and `((Damageable) item.getItemMeta()).getDamage()` to read). For alternate-texture uses, prefer `setCustomModelData` where the code already does.
- **Legacy sign `sign.setLine(i, s)`** (if it errors) → `sign.getSide(Side.FRONT).line(i, net.kyori.adventure.text.Component.text(s))`.
- **`getData()`/`MaterialData`** removals → the modern `BlockData` API.

- [ ] **Step 3: Fix the compiler-surfaced remainder**

For each remaining error, replace the removed/renamed symbol with its documented 26.x equivalent (check `javap` on the paper-api jar for the current signature). If any error requires a genuine design decision (an API with no clear 1:1 replacement), stop and report it as DONE_WITH_CONCERNS with the specific symbol — do not guess a semantically different API.

- [ ] **Step 4: Reach green compile**
